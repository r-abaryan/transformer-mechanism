# Length exposure: execution protocol

Frozen before data generation and training. Implements the [selected decision](length-exposure-decision.md) without changing its criteria. Ten runs: seeds 761/787/809/839/863, baseline versus mixed. Same model initialization per seed, two pre-norm blocks, width16, heads2, FFN32/ReLU, vocabulary19, final LayerNorm, CPU float64. Adam .001, betas .9/.999, eps1e-8, no decay, clipping or warmup. Batch64, exactly 6,000 updates. Mixed uses three pairs on odd updates, four on even; baseline always three. Position start +4 throughout. No architecture change.

Generator 20270101. Exclude previous full mappings in reserved-cycle, position-training, joint-routing-confirmation, canonical-position, final-length, norm-placement, norm-extension and key-content input artifacts. Exclude all available splits, not just tests. For each value subset, draw unique mappings of sorted sampled keys and randomly assigned distinct values; reject exclusions and duplicate mappings. Three-pair counts per value subset: train80/validation10/test20 (1,600/200/400 mappings). Four-pair: train107/validation14/test28 (1,605/210/420 mappings). Six-pair: test420 only. No six-pair training or validation. Save full mapping exclusions/hashes with the input manifest before training.

Expand each mapping into six distinct randomly sampled orders, every query in each order. Three pairs uses all six possible orders. Answer/rank counts balance exactly; variants are dependent. Whole mappings are disjoint within each length, but smaller submappings may be familiar. Derived key-content mappings are included in exclusions.

Minibatch generator seed+1000 draws three-pair indices on every update in both arms, including mixed even updates where these indices are unused. Four-pair stream uses seed+2000, also advanced every update. Thus odd-update three-pair batches match exactly; baseline receives three-pair data on mixed four-pair updates. Hash both potential index streams. Equal updates/examples do not mean equal tokens/FLOPs; report tokens, sum(batch*n_tokens^2) and elapsed training time including validation/checkpoint overhead. Timing is descriptive, not a hardware benchmark.

Record validation on three/four pairs at updates0/1000/.../6000. Save model, Adam, RNG and report state every1,000; resume only matching provenance. No checkpoint selection. Record nonfinite loss/gradient as failure, without changing recipe. Test predictions begin after all ten attempts. Save final test logits for3/4/6 pairs and report accuracy, CE, all-sampled-variant mapping correctness and queried-rank accuracy.

Keep only if all mixed seeds reach six-pair90%; mean paired six-pair gain >=5 points and no seed worsens; all mixed seeds reach three-pair99% and mean three-pair loss of accuracy <=.5 points. Otherwise reject this recipe under this budget, retaining partial benefits. No significance claim. Verify input exclusions/labels/balance, parameter counts/paired initialization/streams, explicit versus library logits and saved metrics/checkpoints. Stop after ten runs and audit; no tuning or extension.
